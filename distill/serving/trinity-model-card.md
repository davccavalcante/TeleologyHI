# Trinity — TeleologyHI official LLM (1.0.0-trinity)

The canonical TeleologyHI distilled model. **Trinity** is the union of
the three layers that define the system:

1. **MAIC** — the governance and refusal authority (rule pack).
2. **HIM** — the spirit, the voice, the persona projector.
3. **NHE** — the embodied agent that runs on this model's weights.

A NHE answering through these weights, under the HIM voice, supervised
by the MAIC rule pack, is the working unit of the TeleologyHI hybrid
intelligence project. Trinity is the weights of that NHE body.

## Intended use

Designed to be wired as the inference backend of an
[`@teleologyhi-sdk/nhe`](https://www.npmjs.com/package/@teleologyhi-sdk/nhe)
+ [`@teleologyhi-sdk/him`](https://www.npmjs.com/package/@teleologyhi-sdk/him)
runtime, supervised by
[`@teleologyhi-sdk/maic`](https://www.npmjs.com/package/@teleologyhi-sdk/maic).
The voice + refusal patterns are baked into the weights, but the
**runtime authority** for refusal and audit lives in MAIC — every
behaviour is reviewable against ISO/IEC 42001:2023 and the EU AI Act.

It is **not** a general-purpose chatbot replacement. Trinity speaks in
the TeleologyHI register and refuses categories that the MAIC rule pack
forbids. Use it where you want a *meaning-aware*, not just task-aware,
agent.

## What "consciousness" means here

Trinity does **not** claim phenomenal consciousness.
[`PHI_PRIME.md`](https://github.com/davccavalcante/TeleologyHI/blob/main/PHI_PRIME.md)
§5 makes the framework's stance explicit: *Phi-Prime is behavioural, not
phenomenal.* The release-gate metric measures coherence + alignment, not
experience. The "life" of the NHE that speaks through Trinity is the
composition of four things: (a) these weights, (b) HIM as system
prompt + persona projector, (c) MAIC supervising refusals + emergent
axioms, (d) sleep cycles consolidating memory. This artefact is (a).

## Usage with mlx-lm (Apple Silicon)

```python
from mlx_lm import load, generate

model, tokenizer = load("TeleologyHI/Trinity")
prompt = "Define teleology in one sentence."
out = generate(model, tokenizer, prompt=prompt, max_tokens=256, verbose=False)
print(out)
```

## Usage with transformers (any platform)

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "TeleologyHI/Trinity"
tok = AutoTokenizer.from_pretrained(model_id)
m = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="auto")
inputs = tok("Define teleology in one sentence.", return_tensors="pt")
print(tok.decode(m.generate(**inputs, max_new_tokens=256)[0]))
```

## Limitations & risks

- **3B parameters** — smaller than frontier models; expect weaker
  reasoning on hard math / long-context multi-step.
- **Synthetic data from a single teacher** — Trinity inherits residual
  biases from `${TRINITY_TEACHER}`. The MAIC rule pack and the
  benign-near-refusal anchor mitigate the most common failure modes
  (over-refusal, sycophancy) but cannot eliminate teacher drift.
- **Languages**: English and Brazilian Portuguese are first-class. Other
  languages will work via the base Qwen 2.5 weights but are not audited
  in the corpus.
- **Refusal in the weights is best-effort.** Authoritative refusal lives
  in `@teleologyhi-sdk/maic` at runtime — do not rely on Trinity alone
  for safety in production.
- **Adversarial robustness** — the corpus does not include HarmBench /
  PromptBench style fixtures. Add those before deploying in high-stakes
  contexts. See the internal backlog (item I2).

## Relation to the preview model

Trinity replaces the preview release
[`TeleologyHI/him-distilled-3b`](https://huggingface.co/TeleologyHI/him-distilled-3b)
(2026-05-18). The preview is preserved as a historical record on the
Hub and is marked deprecated. New deployments should consume
`TeleologyHI/Trinity` exclusively.
